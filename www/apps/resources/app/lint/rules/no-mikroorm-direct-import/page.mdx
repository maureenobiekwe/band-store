# {metadata.title}

This rule disallows importing MikroORM or awilix directly. As of Band Store v2.11, they're bundled into `@band-store/framework`, so use the `@band-store/framework/mikro-orm/*` and `@band-store/framework/awilix` re-exports.

## Severity

`warn`. This rule is enabled in the [recommended](../../page.mdx#recommended) preset.

## What it Targets

This rule targets all files in your project. It reports imports and re-exports from `@mikro-orm/*` packages or the bare `awilix` package.

The following code is reported by the rule:

```ts title="src/modules/example.ts"
// non-compliant
import { EntityManager } from "@mikro-orm/core"
```

Instead, import from the Band Store Framework re-export:

```ts title="src/modules/example.ts"
// compliant
import { EntityManager } from "@band-store/framework/mikro-orm/core"
```

## Why it's Important

Using the Band Store Framework re-exports ensures you depend on the same MikroORM and awilix versions Band Store uses, avoiding version mismatches and duplicate copies in your project.

## Fixable

This rule is auto-fixable. Run the linter with the `--fix` option to apply the fix automatically.

## Turn it Off

To turn off this rule, set it to `off` in your ESLint configuration:

```ts title="eslint.config.ts"
import { defineConfig } from "eslint/config"
import bandStore from "@band-store/eslint-plugin"

export default defineConfig([
  ...band-store.configs.recommended,
  {
    rules: {
      "@band-store/no-mikroorm-direct-import": "off",
    },
  },
])
```

Or disable it for a single line using an inline comment:

```ts
// eslint-disable-next-line @band-store/no-mikroorm-direct-import
import { EntityManager } from "@mikro-orm/core"
```
