# {metadata.title}

In this guide, you'll learn how Band Store uses the Inventory Module in its commerce flows, including product variant creation, adding to cart, order placement, order fulfillment, and order return.

## Product Variant Creation

When a product variant is created and its `manage_inventory` property's value is `true` and the variant's `inventory_items` are set, the Band Store application creates an inventory item associated with that product variant.

<Note title="Tip">

This flow is implemented within the [createProductVariantsWorkflow](/references/band-store-workflows/createProductVariantsWorkflow)

</Note>

## Add to Cart

When a product variant with `manage_inventory` set to `true` is added to the cart, the Band Store application checks whether there's sufficient stocked quantity. If not, an error is thrown and the product variant won't be added to the cart.

<Note title="Tip">

This flow is implemented within the [addToCartWorkflow](/references/band-store-workflows/addToCartWorkflow)

</Note>

## Order is Placed

When an order is placed, the Band Store application creates a reservation item for each product variant with `manage_inventory` set to `true`.

<Note title="Tip">

This flow is implemented within the [completeCartWorkflow](/references/band-store-workflows/completeCartWorkflow)

</Note>

!A diagram showcasing how the Inventory Module is used in the order placement flow

## Order Fulfillment

When an item in an order is fulfilled and the associated variant has its `manage_inventory` property set to `true`, the Band Store application performs the following for each of the item's reservations:

- Subtracts the fulfilled quantity, multiplied by the inventory item's required quantity, from the `stocked_quantity` in the inventory level associated with the variant's inventory item.
- Decreases the `reserved_quantity` of the inventory level by the same quantity.
- Deletes the reservation item if its full quantity is fulfilled, or decreases the reservation item's quantity if only part of it is fulfilled.

Learn more in the [Reservations Lifecycle](../reservations-lifecycle/page.mdx) guide.

<Note title="Tip">

This flow is implemented within the [createOrderFulfillmentWorkflow](/references/band-store-workflows/createOrderFulfillmentWorkflow)

</Note>

<Note>

Each fulfilled item whose variant has `manage_inventory` enabled must have an associated inventory reservation, otherwise the [createOrderFulfillmentWorkflow](/references/band-store-workflows/createOrderFulfillmentWorkflow) throws an error. Reservations are created automatically when an order is placed through the [completeCartWorkflow](/references/band-store-workflows/completeCartWorkflow). If you create an order with a workflow that doesn't create reservations, such as [createOrderWorkflow](/references/band-store-workflows/createOrderWorkflow), use the [createReservationsWorkflow](/references/band-store-workflows/createReservationsWorkflow) to create reservations before fulfilling the order, and set each reservation's `line_item_id` to the order item's ID.

</Note>

## Order Return

When an item in an order is returned and the associated variant has its `manage_inventory` property set to `true`, the Band Store application increments the `stocked_quantity` of the inventory item's level with the returned quantity.

<Note title="Tip">

This flow is implemented within the [confirmReturnReceiveWorkflow](/references/band-store-workflows/confirmReturnReceiveWorkflow)

</Note>

!A diagram showcasing how the Inventory Module is used in the order return flow

### Dismissed Returned Items

If a returned item is considered damaged or is dismissed, its quantity doesn't increment the `stocked_quantity` of the inventory item's level.
