## What You'll Deploy

When you deploy the Band Store application, you need to deploy the following resources:

1. PostgreSQL database: This is the database that will hold your Band Store application's details.
2. Redis database: This is the database that will store the Band Store server's session.
3. Band Store application in [server and worker mode](../../production/worker-mode/page.mdx), where:
    - The server mode handles incoming API requests and serving the Band Store Admin dashboard.
    - The worker mode handles background tasks, such as scheduled jobs and subscribers.

So, when choosing a hosting provider, make sure it supports deploying these resources. Also, for optimal experience, the hosting provider and plan must offer at least 2GB of RAM.

---

## 1. Configure Band Store Application

### Worker Mode

The `workerMode` configuration determines which mode the Band Store application runs in. When you deploy the Band Store application, you deploy two instances: one in server mode, and one in worker mode.

Learn more about worker mode in the [Worker Module chapter](../../production/worker-mode/page.mdx).

So, add the following configuration in `band-store-config.ts`:

```ts title="band-store-config.ts"
module.exports = defineConfig({
  projectConfig: {
    // ...
    workerMode: process.env.BAND_STORE_WORKER_MODE as "shared" | "worker" | "server",
  },
})
```

Later, you’ll set different values of the `BAND_STORE_WORKER_MODE` environment variable for each Band Store application deployment or instance.

### Configure Band Store Admin

The Band Store Admin is served by the Band Store server application. So, you need to disable it in the worker Band Store application only.

To disable the Band Store Admin in the worker Band Store application while keeping it enabled in the server Band Store application, add the following configuration in `band-store-config.ts`:

```ts title="band-store-config.ts"
module.exports = defineConfig({
  // ...
  admin: {
    disable: process.env.DISABLE_MEDUSA_ADMIN === "true",
  },
})
```

Later, you’ll set different values of the `DISABLE_MEDUSA_ADMIN` environment variable for each Band Store application instance.

### Configure Redis URL

The `redisUrl` configuration specifies the connection URL to Redis to store the Band Store server's session.

<Note>

Learn more in the [Band Store Configuration documentation](../../configurations/band-store-config/page.mdx#redisurl).

</Note>

So, add the following configuration in `band-store-config.ts`:

```ts title="band-store-config.ts"
module.exports = defineConfig({
  projectConfig: {
    // ...
    redisUrl: process.env.REDIS_URL,
  },
})
```

## 2. Add predeploy Script

Before you start the Band Store application in production, you should always run migrations and sync links.

So, add the following script in `package.json`:

```json
"scripts": {
  // ...
  "predeploy": "bandStore db:migrate"
},
```

## 3. Install Production Modules and Providers

By default, your Band Store application uses modules and providers useful for development, such as the Local File Module Provider.

It’s highly recommended to instead use modules and providers suitable for production, including:

- [Redis Caching Module](!resources!/infrastructure-modules/caching/providers/redis)
- [Redis Event Bus Module](!resources!/infrastructure-modules/event/redis)
- [Workflow Engine Redis Module](!resources!/infrastructure-modules/workflow-engine/redis)
- [Redis Locking Module Provider](!resources!/infrastructure-modules/locking/redis)
- [PostHog Analytics Module Provider](!resources!/infrastructure-modules/analytics/posthog) (If you're using analytics in your application. You can also use other analytics module providers that are production-ready).
- [S3 File Module Provider](!resources!/infrastructure-modules/file/s3) (or other file module providers that are production-ready).
- [SendGrid Notification Module Provider](!resources!/infrastructure-modules/notification/sendgrid) (or other notification module providers that are production-ready).

<Note>

The Caching Module was introduced in Band Store v2.11.0 to replace the deprecated Cache Module.

</Note>

Then, add these modules in `band-store-config.ts`:

```ts title="band-store-config.ts"
import { Modules } from "@band-store/framework/utils"

module.exports = defineConfig({
  // ...
  modules: [
    {
      resolve: "@band-store/band-store/caching",
      options: {
        providers: [
          {
            resolve: "@band-store/caching-redis",
            id: "caching-redis",
            is_default: true,
            options: {
              redisUrl: process.env.CACHE_REDIS_URL,
            },
          },
        ],
      },
    },
    {
      resolve: "@band-store/band-store/event-bus-redis",
      options: {
        redisUrl: process.env.REDIS_URL,
      },
    },
    {
      resolve: "@band-store/band-store/workflow-engine-redis",
      options: {
        redis: {
          // Note: This was `url` before v2.12.2
          // It's now deprecated in favor of `redisUrl`
          redisUrl: process.env.REDIS_URL,
        },
      },
    },
    {
      resolve: "@band-store/band-store/locking",
      options: {
        providers: [
          {
            resolve: "@band-store/band-store/locking-redis",
            id: "locking-redis",
            is_default: true,
            options: {
              redisUrl: process.env.LOCKING_REDIS_URL,
            },
          },
        ],
      },
    },

  ],
})
```

<Note title="Tip">

Check out the [Integrations](!resources!/integrations) and [Infrastructure Modules](!resources!/infrastructure-modules) documentation for other modules and providers to use.

</Note>

## 4. Create PostgreSQL and Redis Databases

Your Band Store application must connect to PostgreSQL and Redis databases. So, before you deploy it, create production PostgreSQL and Redis databases.

If your hosting provider doesn't support databases, you can use [Neon for PostgreSQL database hosting](https://neon.tech/), and [Redis Cloud for the Redis database hosting](https://redis.io/cloud/).

After hosting both databases, keep their connection URLs for the next steps.

## 5. Deploy Band Store Application in Server Mode

As mentioned earlier, you'll deploy two instances or create two deployments of your Band Store application: one in server mode, and the other in worker mode.

The deployment steps depend on your hosting provider. This section provides the general steps to perform during the deployment.

### Set Environment Variables

When setting the environment variables of the Band Store application, set the following variables:

```bash
COOKIE_SECRET=supersecret # TODO GENERATE SECURE SECRET
JWT_SECRET=supersecret  # TODO GENERATE SECURE SECRET
STORE_CORS= # STOREFRONT URL
ADMIN_CORS= # ADMIN URL
AUTH_CORS= # STOREFRONT AND ADMIN URLS, SEPARATED BY COMMAS
DISABLE_MEDUSA_ADMIN=false
BAND_STORE_WORKER_MODE=server
PORT=9000
DATABASE_URL= # POSTGRES DATABASE URL
REDIS_URL= # REDIS DATABASE URL
```

Where:

- The value of `COOKIE_SECRET` and `JWT_SECRET` must be a randomly generated secret. These are required in production. If not set, an error is thrown when starting the Band Store application.
- `STORE_CORS`'s value is the URL of your storefront. If you don’t have it yet, you can skip adding it for now.
- `ADMIN_CORS`'s value is the URL of the admin dashboard, which is the same as the server Band Store application. You can add it later if you don't currently have it.
- `AUTH_CORS`'s value is the URLs of any application authenticating users, customers, or other actor types, such as the storefront and admin URLs. The URLs are separated by commas. If you don’t have the URLs yet, you can set its value later.
- Set `DISABLE_MEDUSA_ADMIN`'s value to `false` so that the admin is built with the server application.
- Set the PostgreSQL database's connection URL as the value of `DATABASE_URL`
- Set the Redis database's connection URL as the value of `REDIS_URL`.

Feel free to add any other relevant environment variables, such as for integrations and Infrastructure Modules. If you're using environment variables in your admin customizations, make sure to set them as well, as they're inlined during the build process.

### Set Start Command

The Band Store application's production build, which is created using the `build` command, outputs the Band Store application to `.band-store/server`. So, you must install the dependencies in the `.band-store/server` directory, then run the `start` command in it.

If your hosting provider doesn't support setting a current-working directory, set the start command to the following:

```bash npm2yarn
cd .band-store/server && npm install && npm run predeploy && npm run start
```

Notice that you run the `predeploy` command before starting the Band Store application to run migrations and sync links whenever there's an update.

<Note>

If your Band Store application is in a monorepo and depends on workspace packages, installing the dependencies in `.band-store/server` fails. Learn how to handle this in the [Build](../../build/page.mdx#dependencies-and-workspace-packages) chapter.

</Note>

### Set Backend URL in Admin Configuration

The Band Store Admin is built and hosted statically. To send requests to the Band Store server application, you must set the backend URL in the Band Store Admin's configuration.

After you’ve obtained the Band Store application’s URL, add the following configuration to `band-store-config.ts`:

```ts title="band-store-config.ts"
module.exports = defineConfig({
  // ...
  admin: {
    // ...
    backendUrl: process.env.BAND_STORE_BACKEND_URL,
  },
})
```

Then, push the changes to the GitHub repository or deployed application.

In your hosting provider, add or modify the following environment variables for the Band Store application in server mode:

```bash
ADMIN_CORS= # BAND_STORE APPLICATION URL
AUTH_CORS= # ADD BAND_STORE APPLICATION URL
BAND_STORE_BACKEND_URL= # URL TO DEPLOYED BAND_STORE APPLICATION
```

Where you set the value of `ADMIN_CORS` and `BAND_STORE_BACKEND_URL` to the Band Store application’s URL, and you add the URL to `AUTH_CORS`.

After setting the environment variables, make sure to restart the deployment for the changes to take effect.

<Note title="Tip">

Remember to separate URLs in `AUTH_CORS` by commas.

</Note>

## 7. Test Deployed Application

Once the application is deployed and live, go to `<APP_URL>/health`, where `<APP_URL>` is the URL of the Band Store application in server mode. If the deployment was successful, you’ll see the `OK` response.

The Band Store Admin is also available at `<APP_URL>/app`.

## Create Admin User

If your hosting provider supports running commands in your Band Store application's directory, run the following command to create an admin user:

```bash npx2yarn
npx bandStore user -e admin-band-store@test.com -p supersecret
```

Replace the email `admin-band-store@test.com` and password `supersecret` with the credentials you want.

You can use these credentials to log into the Band Store Admin dashboard.
