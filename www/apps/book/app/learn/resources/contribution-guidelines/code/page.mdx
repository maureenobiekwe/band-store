# {metadata.title}

Thank you for your interest in contributing to Band Store's codebase! This guide walks you through setting up a local development environment, linking your fork to a test project, and iterating on changes with hot reload.

<Note title="Tip">

This guide is specific to contributing to Band Store's codebase. If you're interested in contributing to the documentation, check out the [Docs Contribution Guidelines](../docs/page.mdx).

</Note>

## What Can You Contribute?

You can contribute to Band Store's codebase in the following ways:

- Bug fixes to packages, modules, or plugins.
- New features, after opening an issue to confirm the approach with the team.
- Improvements to tooling and the contributor developer experience.

<Note>

Before writing code, make sure there's an issue for your change. This lets others weigh in before you invest time. See Issues before PRs.

</Note>

## Linking Your Fork to a Test Project

To test local changes, point your test project's `@band-store/*` dependencies at your local packages and resolve every transitive dependency locally.

1. In your test project's `package.json`, replace the `@band-store/*` entries in `dependencies` and `devDependencies` with `file:` references to your fork:

```json
"dependencies": {
  "@band-store/cli": "file:../band-store/packages/cli/band-store-cli",
  "@band-store/framework": "file:../band-store/packages/core/framework",
  "@band-store/band-store": "file:../band-store/packages/band-store"
}
```

2. Add the full set of packages under `resolutions` so transitive dependencies also resolve locally. See the complete list in `CONTRIBUTING.md`.

## Iterating with Watch Mode

After building your fork, you can iterate without a full rebuild on each change.

- For most packages, use the package's `dev` or `watch` script.
- For plugin packages (`packages/plugins/*`), use the watch flow:

```bash
# inside the plugin package
yarn watch       # swc watch + yalc publish on change (bandStore plugin:develop)
yarn link:watch  # publish once, then watch
```

Under the hood, `bandStore plugin:develop` watches your source, transforms it with `@swc/core`, and republishes via `yalc` so your linked test project picks up changes automatically.

---

## Opening a Pull Request

Branch out from `develop`, make your changes, and open a pull request against `develop`. A team member will review within a few days.
