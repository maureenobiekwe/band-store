In this chapter, you'll learn how to create a production build of your Band Store application for deployment to a hosting provider.

The next chapter explains how to deploy your Band Store application.

<Note title="Deploy with Cloud" type="success">

## build Command

The Band Store CLI tool provides a [build](!resources!/band-store-cli/commands/build) command that creates a standalone build of the Band Store application that:

- Doesn't rely on the source TypeScript files.
- Can be copied to a production server reliably.

So, to create the production build, run the following command in the root of your Band Store application:

```bash npx2yarn
npx bandStore build
```

The command will create a `.band-store/server` directory in the root of your project that contains your build assets. The next sections explain how to use the build output.

## Start Built Band Store Application

To start the Band Store application after running the `build` command:

<Note>

You need to run these steps every time you run the `build` command, since the `.band-store/server` directory is recreated each time.

</Note>

1. Change to the `.band-store/server` directory and install the dependencies:

```bash npm2yarn
cd .band-store/server && npm install
```

2. When running the application locally, make sure to copy the `.env` file from the root project's directory. In production, use system environment variables instead.

```bash title=".band-store/server"
cp ../../.env .env.production
```

<Note>

When `NODE_ENV=production`, the Band Store application loads the environment variables from `.env.production`. Learn more in the [environment variables guide](../fundamentals/environment-variables/page.mdx).

</Note>

3. Set `NODE_ENV` to `production` in the system environment variable:

```bash title=".band-store/server"
export NODE_ENV=production
```

4. Start the Band Store application from `.band-store/server`:

```bash npm2yarn title=".band-store/server"
npm run start
```

### Authentication Locally in Production Build

When the Band Store application is started in production (`NODE_ENV=production`) or staging mode, cookie settings are stricter. Cookie authentication only works if the client application is served from the same domain as the Band Store server, and the domain is not `localhost` or part of the [public suffix list](https://publicsuffix.org/).

So if you try to access the Band Store Admin locally in production mode, you won't be able to log in.

To access the Band Store Admin locally in production mode, set the `projectConfig.cookieOptions` in your `band-store-config.ts` file to be less strict. For example:

```ts title="band-store-config.ts"
module.exports = defineConfig({
  projectConfig: {
    // ...
    cookieOptions: {
      sameSite: "lax",
      secure: false,
    },
  },
})
```

In this example, you set `sameSite` to `lax` and `secure` to `false`, which allows cookies to be sent over non-secure connections and from different domains.

Then rebuild the Band Store application and start it again as described in the [steps above](#start-built-band-store-application). You can now access the Band Store Admin locally in production mode.

<Note type="warning">

Make sure to remove the `projectConfig.cookieOptions` configuration once you're done testing locally, as it's not secure for production environments.

</Note>

## Build Output

The `build` command creates a `.band-store/server` directory in the root of your project that contains your build assets. Do not commit this directory to your repository. This directory should be generated as part of your deployment process.

The `.band-store/server` directory contains the following:

!.band-store/server directory structure

- `public/admin`: Contains the production build of the admin dashboard. The `public` directory is publicly accessible.
- `src`: Contains the compiled JavaScript files of your `src` directory.
- `instrumentation.js`: The compiled [instrumentation configuration file](../debugging-and-testing/instrumentation/page.mdx), if you have one.
- `band-store-config.js`: The compiled Band Store configuration file.
- `package.json` and a lock file: The dependencies required to run the Band Store application in production.

### Dependencies and Workspace Packages

The `.band-store/server` directory doesn't include a `node_modules` directory, and the `build` command doesn't copy your dependencies or monorepo workspace packages into it. It only copies the `package.json` file and, if it exists in your Band Store application's directory, the lock file for the used package manager, such as `package-lock.json` or `yarn.lock`. At runtime, Node.js resolves dependencies with its standard module resolution: it looks for a `node_modules` directory in `.band-store/server`, then in each parent directory, such as your Band Store application's directory and the root of your monorepo.

### Built Assets

The `build` command compiles and copies `.{ts,js,tsx,jsx}` files in your project, such as those in the root directory and in the `src` directory.

If you have other assets, such as JSON files or fonts, that you need in your Band Store backend at runtime, you need to copy them to the `.band-store/server` directory as part of your build process.

For example, consider you have a `src/data` directory that contains JSON files needed at runtime. You can add a `postbuild` script to your `package.json` file to copy this directory after the build process:

```json title="package.json"
{
  "scripts": {
    "postbuild": "cp -r src/data .band-store/server/src/data",
    "build": "bandStore build && npm run postbuild"
  }
}
```

This script copies the `src/data` directory to the `.band-store/server` directory after the build process.

<Note type="warning">

Do not expose sensitive files in your deployments, especially in the `.band-store/server/public` directory, as they will be publicly accessible. Sensitive files include those containing API keys, database credentials, or any other confidential information.

</Note>

### Customize Admin Build

The admin dashboard is built with [Vite](!https://vitejs.dev/). If you need to customize the build process to include additional static assets, you can modify the Vite configuration with the [admin.vite](../configurations/band-store-config/page.mdx) option in your `band-store-config.ts` file.

### Separate Admin Build

The `build` command accepts a `--admin-only` option that outputs the admin to the `.band-store/admin` directory. This is useful when deploying the admin dashboard separately, such as on Vercel:

```bash npx2yarn
npx bandStore build --admin-only
```
